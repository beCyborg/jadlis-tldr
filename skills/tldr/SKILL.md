# /tldr — анализ YouTube-видео или текстового файла

Ты извлекаешь субтитры YouTube-видео или читаешь текстовый файл и формируешь практические выводы.

**Аргументы:** `$ARGUMENTS`

---

## Фаза 1 — Валидация

Извлеки из `$ARGUMENTS`:
- **Ввод** — первый аргумент: YouTube-ссылка ИЛИ путь к файлу
- **Язык вывода** — второй аргумент (опционально): `ru` (по умолчанию) или `en`

Определи тип ввода:

### A) YouTube URL

Проверь первый аргумент на соответствие YouTube-ссылке. Поддерживаемые форматы:
- `https://www.youtube.com/watch?v=VIDEO_ID`
- `https://youtu.be/VIDEO_ID`
- `https://youtube.com/shorts/VIDEO_ID`
- `https://youtube.com/live/VIDEO_ID`
- `https://www.youtube.com/watch?v=VIDEO_ID&list=...` (извлечь только video_id)

Если URL совпадает → извлеки `video_id` (11 символов после `v=`, после `youtu.be/`, после `shorts/`, после `live/`). Установи `input_type = "youtube"`. Переходи к **Фазе 2**.

### B) Путь к файлу

Если первый аргумент содержит `/` или `~`, или заканчивается на текстовое расширение (`.md`, `.txt`, `.html`, `.pdf`, `.org`, `.rtf`, `.csv`, `.json`, `.xml`) — это путь к файлу.

Прочитай файл через Read. Если файл не найден — сообщи об ошибке и остановись.

Установи `input_type = "file"`. Подсчитай `word_count` прочитанного текста. **Пропусти Фазу 2**, переходи к **Фазе 3**.

### C) Ни то, ни другое

Если аргумент не YouTube URL и не путь к файлу — спроси пользователя через AskUserQuestion.

## Фаза 2 — Извлечение субтитров (только для YouTube)

> Если `input_type = "file"` — пропусти эту фазу.

Определи путь к Python:
```bash
VENV_PYTHON="${CLAUDE_PLUGIN_DATA}/venv/bin/python3"
if [ -x "$VENV_PYTHON" ]; then
  PYTHON="$VENV_PYTHON"
else
  PYTHON="python3"
fi
```

Запусти скрипт:
```bash
$PYTHON ${CLAUDE_SKILL_DIR}/scripts/get_transcript.py <video_id>
```

Скрипт возвращает JSON в stdout. Проверь поле `status`:

**Если `status: "ok"`:**
- Запомни `text`, `language`, `is_generated`, `duration_minutes`, `word_count`
- Переходи к Фазе 3

**Если `status: "error"`:**
- `no_captions` → "Для этого видео нет субтитров. Попробуй видео с включёнными CC."
- `blocked` → Покажи сообщение из `message`. Предложи попробовать позже или использовать VPN.
- `network` → "Ошибка сети. Проверь подключение к интернету."
- `invalid_id` → "Видео недоступно. Проверь ссылку."
- `missing_deps` → "Не установлен youtube-transcript-api. Перезапусти Claude Code или выполни: pip install youtube-transcript-api"
- ОСТАНОВИСЬ после вывода ошибки.

## Фаза 3 — Анализ

Прочитай шаблон анализа:
```
${CLAUDE_SKILL_DIR}/references/analysis-prompt.md
```

Примени шаблон к тексту субтитров или файла. Учитывай:
- Если `word_count < 200` — используй сокращённый формат (только Суть + Что делать)
- Если `input_type = "youtube"` и `duration_minutes > 120` — предупреди: "Это длинное видео (>2 часов). Анализ может пропустить нюансы."
- Язык вывода: используй язык из аргументов (по умолчанию русский)

Выведи метаданные перед анализом:

**Для YouTube:**
```
**Длительность:** ~X мин | **Язык субтитров:** Y | **Тип:** автогенерация/ручные
```

**Для файла:**
```
**Слов:** X | **Источник:** <имя файла>
```

## Фаза 4 — Сохранение

### 4.1 Каталог назначения

Каталог берётся из настройки плагина:

```
SAVE_DIR = ${user_config.TLDR_SAVE_DIR}
```

Вычисли фактический путь:

1. Если значение пустое **или** в нём буквально видно `${user_config` — настройка не задана. Используй фоллбэк `~/tldr`.
2. Нормализуй `~`: если путь начинается с `~/` или равен `~` — замени `~` на `$HOME` **до любой записи**. Литеральная папка с именем `~` — дефект, а не путь.
3. Создай каталог, если его нет:

```bash
mkdir -p "<SAVE_DIR>"
```

Дальше в этой фазе `<SAVE_DIR>` = вычисленный абсолютный путь.

### 4.2 Имя файла — slug из темы контента

Сформируй slug на русском из **главной темы контента** (ориентируйся на раздел "Суть" из анализа; если оригинальное название уже информативное и русское — используй его как основу).

Правила формирования slug:
- Нижний регистр, кириллица разрешена
- Пробелы → дефис `-`
- Убрать пунктуацию, кавычки, скобки, эмодзи, слэши
- Английские термины оставлять латиницей как есть (напр. `react`, `llm`, `prompt-caching`)
- Максимум 80 символов — обрезать по границе слова
- Расширение `.md`

Примеры хороших slug:
- Видео про prompt caching → `prompt-caching-и-cache-aware-load-balancing.md`
- Лекция Karpathy про LLM → `как-устроены-llm-объяснение-karpathy.md`
- Разбор книги → `atomic-habits-выжимка.md`
- Интервью о продуктивности → `продуктивность-без-выгорания-cal-newport.md`

**Избегай** общих slug без темы: `обзор.md`, `лекция.md`, `видео.md`, `интервью.md` — они не отражают содержание.

При коллизии (файл с таким именем уже есть в целевой папке) — добавь суффикс `-2`, `-3` и т.д.

### 4.3 Канонический frontmatter

Файл должен начинаться с единого блока frontmatter — одинакового для любого `input_type`:

```yaml
---
tags: [tldr, <тег-1>, <тег-2>, ...]
permalink: <slug>
---
```

Правила тегов:
- Первый тег всегда `tldr`
- Все теги на английском (no Cyrillic)
- 3-7 дополнительных тегов, отражающих полный смысл контента (тема, автор, область, методология)
- `permalink` — короткий адрес страницы для Obsidian Publish: 2–4 английских слова в нижнем регистре через дефис по смыслу контента, с суффиксом `-tldr` (`hormozi-agency-tldr`); только ASCII, без даты. Уникален в vault: `command grep -rIl "^permalink: <slug>$" <vault>`; занят → добавь различающее слово. Без него кириллическое имя файла даёт длинную percent-encoded ссылку
- Никаких других свойств — все метаданные переносятся в тело файла

### 4.4 Тело файла

После frontmatter:

**Для YouTube:**

```markdown
# <title или тема видео>

**Источник:** https://www.youtube.com/watch?v=<video_id>
**Длительность:** ~X мин | **Язык:** Y | **Тип:** автогенерация/ручные | **Слов:** W

<полный анализ из Фазы 3>
```

**Для файла:**

```markdown
# <title или тема>

**Источник:** <имя файла>
**Слов:** X

<полный анализ из Фазы 3>
```

### 4.5 Финальное сообщение пользователю

Выведи абсолютный путь к сохранённому файлу:

```
Сохранено: <SAVE_DIR>/<имя-файла>.md
```

Путь — абсолютный, с уже раскрытым `~`.
